# Codex Resets 预判仪表盘 — 升级计划

## 概述

基于对 willcodexquotareset.com、codex-reset.com 等竞品的深度研究，将现有的"模拟信号模型"升级为**基于真实重置历史和公开信号的预测系统**。核心改进：用真实重置记录替换模拟数据、引入 Tibo 推文 + OpenAI 状态页 + 时间衰减等多源信号、增加个人用量追踪器和存储重置管理、优化概率模型使其贴近真实重置节奏。

## 技术方案

| 维度 | 选择 | 理由 |
|------|------|------|
| 数据获取 | RSS 代理 + 客户端 fetch | 纯前端 SPA 无法直接爬取 Twitter；使用 rss2json 等公开 RSS 代理获取 Tibo 推文和 OpenAI 状态页 |
| 重置历史 | 硬编码真实数据 | 自 2025-09 以来 47+ 次已验证重置，含时间、推文链接、触发原因 |
| 概率模型 | 时间衰减 + 间隔统计 + 信号加权 | 参考竞品方法：基础概率随距上次重置天数增长，信号（推文暗示、故障报告、产品发布）作为加成/扣减 |
| 个人数据 | localStorage | `/status` 数据留在用户浏览器，不上传服务器 |
| 存储重置 | localStorage | 跟踪发放日期和 30 天过期倒计时 |
| 通知 | 已有 Supabase 邮箱订阅 | 概率超阈值时邮件提醒（后端需 Edge Function 定时检查） |

## 功能模块

### 1. 真实重置历史数据库

- 硬编码 47+ 条已验证重置记录（2025-09 至今）
- 字段：`{ date: string, time: string, tweetUrl: string, reason: string, interval_days?: number }`
- 计算统计指标：中位间隔（~3.8 天）、近期节奏、最常见时间窗口（UTC 17:00-24:00）

### 2. 多源信号雷达

替换现有 5 路模拟信号，改为 4 路真实信号轨道：

| 信号轨道 | 数据源 | 检测逻辑 |
|---------|--------|---------|
| Tibo 推文 | RSS 代理抓取 @thsottiaux | 关键词匹配（reset/重置/limits/usage）+ 语义分类（已确认/暗示/无关） |
| OpenAI 状态页 | status.openai.com RSS | 检测 Codex/Work 相关事故 |
| 时间冷却 | 本地计算 | 距上次重置的天数，越久概率越高 |
| 产品发布噪音 | Tibo 推文 + 新闻 | 模型发布、里程碑公告等 |

### 3. 改进的概率模型

```
基础概率 = f(距上次重置天数, 历史间隔分布)
  - 使用历史间隔的中位数和加权均值
  - 时间越长，概率越高（但不超过上限）
  - 静默期概率保持平稳（不采用"越拖越该来"模型）

信号加成：
  - Tibo 发布暗示推文: +10~15%
  - OpenAI 故障报告: +5~8%
  - 产品发布/里程碑: +8~12%
  - 刚完成重置（<2天）: -10~15%
  - 高痛感措辞（社区抱怨）: -3~5%（老化后衰减）
```

### 4. 个人用量追踪器

- 用户输入 `/status` 中的每周窗口重置时间和使用百分比
- 本地计算消耗速度 vs 剩余时间
- 可视化：进度条 + "你能撑到重置吗？" 判断
- 数据仅存 localStorage

### 5. 存储重置管理器

- 用户手动输入存储重置的发放日期
- 自动计算 30 天过期倒计时
- 支持多个存储重置同时跟踪
- 数据存 localStorage

### 6. 重置时间分布图

- 按小时分桶统计所有已记录公告的时间分布
- 转换到用户本地时区
- 柱状图可视化（使用 Recharts）

## 实施步骤

### 阶段一：原型设计

1. 加载 `design-canvas` 技能，基于现有仪表盘风格和新功能需求设计原型。新增页面：个人用量追踪器（嵌入首页）、存储重置管理器（嵌入首页）、信号雷达改进布局。原型完成后提示用户确认，调用 done 工具提交等候确认。

### 阶段二：代码开发

2. **真实重置历史 + 概率模型重构** — 替换 `src/lib/prediction.ts` 中的模拟数据，嵌入 47+ 条真实重置记录，实现基于时间衰减 + 间隔统计 + 信号加权的概率计算引擎。关键文件：`src/lib/prediction.ts`、`src/lib/reset-data.ts`、`src/types/reset.ts`

3. **多源信号雷达** — 实现 RSS 代理获取 Tibo 推文和 OpenAI 状态页，客户端解析并分类信号。关键文件：`src/lib/signals.ts`、`src/sections/SignalPanel.tsx`

4. **个人用量追踪器 + 存储重置管理器** — 新建两个交互组件，用户输入 `/status` 数据和存储重置发放日期，localStorage 持久化。关键文件：`src/sections/UsageTracker.tsx`、`src/sections/BankedResets.tsx`

5. **重置时间分布图 + 页面集成** — 新增按小时分桶的时间分布柱状图，将所有新模块集成到 Home 页面布局中。关键文件：`src/sections/TimeDistribution.tsx`、`src/pages/Home.tsx`

6. **代码检查与验证** — TypeScript 编译检查、构建验证、日志健康检查。

## 页面规格

##### @page(/) 重置预判仪表盘

**核心职责**：实时展示 Codex 下次善意重置的概率预测、多源信号雷达、个人用量追踪和存储重置管理。
**访问路径**：直接访问根路径。
**布局**：
- 顶部：状态栏（实时状态 + 模型版本 + 上次重置时间）
- 主内容区 12 列网格：
  - 左列（8 列）：重置预估面板 + 概率仪表盘 → 概率脉搏曲线 → 信号雷达 → 重置时间分布图
  - 右列（4 列）：邮箱订阅 → 个人用量追踪器 → 存储重置管理器 → 重置历史 → 模型说明

**重置预估面板设计说明**（替代原倒计时方案）：
- 显示"最可能重置窗口"时间范围（如 Aug 20 17:00 - 23:00 UTC），而非精确倒计时
- 等待进度条：显示"已等待 X 天 / 中位间隔 3.8 天"，直观展示当前等待位置
- 规划建议：根据概率给出明确操作建议（"谨慎使用" / "建议等待" / "正常使用"）
- 不预设精确倒计时目标，避免给用户虚假确定感

**状态**：
- 加载态：信号模型初始化动画
- 错误态：RSS 获取失败时显示降级提示（使用缓存数据）
